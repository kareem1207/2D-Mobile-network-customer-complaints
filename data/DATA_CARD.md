# Data card — `code_mixed_complaints.csv`

| | |
|---|---|
| **Domain** | Mobile network customer complaints / feedback (variant 2D) |
| **Language** | Telugu in Roman script mixed with English (code-mixed), no Telugu script |
| **Size** | 3,000 reviews: train 2,100 · validation 450 · test 450, each class-balanced (700/150/150 per class) |
| **Classes** | `negative`, `positive`, `mixed` (balanced, 1,000 each) |
| **Length** | 2–83 tokens, mean 26.6, median 20 |
| **Source** | **Synthetic.** Generated by `src/generate_dataset.py` (seed 42) from hand-written phrase banks. **Not real customer text.** |
| **Labels** | Programmatic: assigned by construction from the decisive phrase(s), following `ANNOTATION_GUIDE.md`. No human annotator has labelled this file. |

## Why synthetic?
No labelled Telugu–English mobile-network complaint corpus is publicly available and the task allows only a
three-day window. Using the generator keeps the data fully reproducible and licence-clean (MIT), but **results on it
are not evidence of real-world accuracy** — see limitations.

## Columns
`id, text, label, category, spelling_noise, split, phrase_pool, n_tokens`

* `category` — structure of the review: `plain`, `polite_opening` (courtesies/praise, complaint last),
  `long_buried` (3–6 neutral background sentences before the decisive one), `sarcasm` (negative, positive-sounding),
  `negation` (*"problem ledu"* = positive, *"baaga ledu"* = negative), `mixed_distant` (praise and complaint separated by background sentences).
* `spelling_noise` — 1 if Romanised-Telugu spelling variants / letter-swap typos were injected (about half of reviews).
* `phrase_pool` — `seen` (decisive phrase also possible in training) or `unseen` (phrase held out of training:
  the last 3 of 10 phrases per aspect and polarity). Half of validation and test reviews are `unseen`.

## Class balance by category
Negative: plain 29%, polite 24%, long_buried 21%, sarcasm 16%, negation 10%.
Positive: plain 34%, polite 26%, long_buried 22%, negation 19%.
Mixed: plain 23%, polite 18%, long_buried 27%, mixed_distant 32%.

## Splits and leakage control
Stratified by construction; no text appears in more than one split (exact normalised-text de-duplication).
The vocabulary is built from the training split only (746 word types).

## Known limitations
* Templates: the grammar is far narrower than real reviews. Real code-mixed text has more vocabulary, slang, emojis, Telugu script and noisier spelling.
* Shortcuts: `mixed` reviews are longer on average (38 vs 21 tokens) and often contain contrastive connectors (*kani, but, however*), which a model can exploit.
* Single "annotator": label noise is zero by construction, so any κ against these labels would not reflect real annotation ambiguity. A blind 210-item sheet is provided to measure human agreement.
* Six aspects only: signal, speed, calls, billing, care, service/OTP.
